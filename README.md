# Observation Coach

**A little less screen. A little more world.**

Most AI products compete for your attention. Observation Coach uses AI to give your attention back to the world.

A calm, mobile-friendly observation trainer built with **Next.js App Router, TypeScript, Tailwind CSS v4, and MongoDB**. It supports **local open-weight models**, **hosted OpenAI-compatible APIs**, and an explicitly labeled **deterministic guided demo**.

## The experience

```text
Log in → choose 5 / 10 / 20 / 30 minutes → one observation exercise
       → phone away → return → describe one real detail
       → one thoughtful follow-up → an adaptive next invitation
```

No camera, object identification, feeds, competitive scores, or streaks. The “Go Outside” screen hides navigation and has no countdown. You can return when you are ready.

**The goal isn't to make people spend more time with AI. It's to make them need AI less.**

## Run the app

Requirements: Node.js 20.9+ (tested on Node 20.20.2), npm, and MongoDB running as a replica set — **either your already-installed MongoDB (no Docker; `scripts/mongodb-enable-replicaset` enables it in one step) or the included Docker Compose service**. The MongoDB driver requires the Node runtime, not Edge.

**Full Windows/local/Atlas instructions, including the no-Docker path: [DATABASE.md](DATABASE.md).** If you already have `.env.local`, merge its database settings instead of overwriting your LLM configuration.

```powershell
npm ci
Copy-Item .env.example .env.local
docker compose up -d --wait
npm run dev
```

In Windows Command Prompt use `copy`; on macOS/Linux use `cp` instead of `Copy-Item`. The npm scripts use `cross-env` for Windows-compatible environment variables.

Open `http://localhost:3000`. The development server binds to `0.0.0.0` for hosted previews. No API key is required for the default guided demo, but MongoDB must be running for accounts and history.

For a production build:

```bash
npm run build
npm start
```

Set `COOKIE_SECURE=true` behind an HTTPS reverse proxy. Secure cookies are also the default in production if the variable is unset. Use `COOKIE_SECURE=false` only for a trusted, local HTTP setup. For an HTTPS cross-site iframe preview, set `COOKIE_EMBEDDED=true`; cookies then use `SameSite=None; Secure; Partitioned` so login works inside supported embedded browsers. Keep it false for ordinary local use. All mutation origin checks still apply. Next.js telemetry is disabled in the supplied npm scripts.

### Local versus hosted database

Local `.env.local`:

```dotenv
APP_ENV=local
MONGODB_URI=mongodb://127.0.0.1:27017/observation_coach?replicaSet=rs0&directConnection=true
MONGODB_DB_NAME=observation_coach
```

Hosted server secrets (see `.env.hosted.example`):

```dotenv
APP_ENV=hosted
MONGODB_URI=mongodb+srv://USER:URL_ENCODED_PASSWORD@YOUR_CLUSTER.mongodb.net/?retryWrites=true&w=majority
MONGODB_DB_NAME=observation_coach
COOKIE_SECURE=true
```

The local Docker named volume survives restarts and `docker compose down`. Do **not** use `down -v` unless deliberately deleting data. Hosted mode requires an explicit Atlas URI and never silently falls back to local storage. Database mode and LLM mode are independent.

**Existing SQLite data is left untouched but is not automatically migrated.** MongoDB starts with its own account/history records. No Atlas credentials were provided, so live Atlas connectivity still needs verification.

### Try the concept in 60 seconds

1. Choose **Try the guided demo** on the home page.
2. Keep **5 minutes** selected and prepare your invitation.
3. Choose **I'm ready to look around**. The app gets out of the way.
4. Tap **I'm back** (there is deliberately no enforced timer).
5. Choose **Try a sample observation**, then reflect with the coach.
6. Answer the follow-up and finish the reflection.
7. See your next invitation, skill signals, and saved field note.

Each demo visitor gets a separate temporary account. Feedback is deterministic, not secretly generated by a model. Demo authentication lasts 24 hours; expired demo records are removed by MongoDB TTL indexes (background cleanup is not instantaneous). Creating a regular account starts a separate history; demo notes are not migrated.

## Configure a model

Keep configuration in `.env.local` or your deployment's secret manager. **Never use `NEXT_PUBLIC_` for model credentials.** Restart the application after changes. An existing session retains its chosen provider; create a new session to use a new provider configuration.

### Local / open-weight

```dotenv
LLM_PROVIDER=local
LOCAL_LLM_BASE_URL=http://localhost:1234/v1
LOCAL_LLM_MODEL=the-model-name-shown-by-your-server
# Optional, if your local endpoint requires authentication
LOCAL_LLM_API_KEY=
```

Compatible endpoint examples:

| Runtime          | Example base URL            |
| ---------------- | --------------------------- |
| LM Studio        | `http://localhost:1234/v1`  |
| Ollama           | `http://localhost:11434/v1` |
| llama.cpp server | `http://localhost:8080/v1`  |

Load an instruction-tuned model with good JSON-following behavior. The app uses `/chat/completions` with standard messages, temperature, and a token budget. It does not require a vendor-specific SDK or `response_format` support. Responses are parsed and validated with Zod.

**The endpoint is reached from the Next.js server.** In the Arena hosted preview, `localhost` refers to the sandbox—not your laptop. Run the application locally beside your model, or configure a hosted endpoint for the preview.

### Hosted preview / demo deployment

```dotenv
LLM_PROVIDER=hosted
HOSTED_LLM_BASE_URL=https://your-compatible-provider.example/v1
HOSTED_LLM_MODEL=your-model-id
HOSTED_LLM_API_KEY=your-server-side-secret
```

Any provider implementing the required OpenAI-compatible chat completions format can be used; an open-weight model hosted by a provider is also suitable. All inference requests go through the server. Regular accounts use this configured provider; the separate guided demo intentionally stays deterministic.

**Current preview status:** no real hosted credentials or local model were supplied. The preview runs in guided-demo mode. Both adapters are implemented and tested against a simulated compatible endpoint, but real inference and coaching quality remain unverified.

If configuration is missing, the model cannot be reached, or the response is invalid, the app shows an actionable error. Submitted reflections are saved before inference. It never silently switches to another provider.

## Why AI belongs here

The useful part is not naming a tree. It's asking a question that meets a person at the detail they actually noticed, then suggesting an exercise that develops a less-practiced skill. Coaching is short, grounded in the user's words, and followed by time away from the screen.

The six progression chapters are attention, description, comparison, change, inference, and deep observation. Six underlying skill signals also track curiosity. These are approximate coaching signals, not scientific measurements or a score to optimize.

### Why local/open-weight AI matters

Observations can be personal, and a reflective outdoor practice should not depend on a cloud account, connectivity, or a proprietary model's availability. Local models allow a fully local deployment, model replacement, and control over data handling. A cloud-only architecture would remove those choices and always send private observations off the device.

Hosted inference is a practical, **explicitly disclosed option** for an accessible preview—not a hidden replacement for the local design.

## Privacy and storage

- Every history, session, and progress record belongs to an authenticated user.
- Local MongoDB stores records in the named Docker volume. Hosted deployments use the configured Atlas database. `MONGODB_URI` and `MONGODB_DB_NAME` are server-only settings.
- Hosted deployment stores observations in the **server-side MongoDB database (normally Atlas)**, not exclusively on the user's device.
- Hosted AI sends relevant reflection context to the configured provider; its retention policy applies.
- A local app + database + local model can keep observations on one machine.
- No analytics, tracking scripts, external font requests, or external image requests.
- Passwords are salted and hashed with scrypt. Login tokens are opaque, HTTP-only, and hashed in the database.
- Drafts are held in the current browser tab's `sessionStorage` and cleared after submission/logout. Submitted text is stored in MongoDB.
- Account deletion removes application records and sessions. It cannot independently erase a hosted provider's retained data or deployment backups.
- The local development volume is not encrypted by this app. Use an encrypted host disk and backups; configure hosted database security and retention appropriately.

### Offline means local, not a disconnected hosted website

All fonts and images are bundled. Once installed and built, a local application/database/model can work without internet access. You must still be able to reach the application server. There is no service worker or browser-only offline database. Hosted inference and some browser voice services need connectivity.

## Logs and debugging

Server logs are plain single-line text on stdout (warnings/errors on stderr):

```text
2026-10-10T09:12:33.412Z INFO  [db] connected to MongoDB {"environment":"local","database":"observation_coach","poolSize":10}
2026-10-10T09:12:34.001Z DEBUG [http] api request {"method":"GET","path":"bootstrap","status":200,"ms":7}
```

- **`LOG_LEVEL`** — `debug | info | warn | error | silent`. Defaults to `debug` for local development and `info` on hosted servers (`APP_ENV=hosted`). Set `LOG_LEVEL=debug` in hosted secrets for verbose diagnostics. Debug lines cover database connections/transactions, authentication events, session lifecycle, LLM adapter calls, and voice dictation state.
- **`LOG_HTTP`** — morgan **Apache “combined”** access logs for every page and API request. They default **on for hosted deployments** and off locally; `LOG_HTTP=true|false` overrides either way. Lines are written raw to stdout so log aggregators can parse them like classic web-server access logs. `/api` lines carry the final status and content length; page lines are logged when the proxy routes the request (the routing status is logged, so a rare server-rendered 500 can appear as 200 — `onRequestError` logs those separately as `unhandled server error`).

Privacy: logs never include passwords, tokens, cookies, connection strings, API keys, emails, reflections, or model prompts. Field names that look secret are redacted automatically, and unknown error messages are dropped (only curated error classes keep their hand-written messages; everything else logs a name and code). Access lines include the request path and query string plus client IP/user agent — the same metadata any web-server access log carries.

Logs are written with `next dev`, `next start`, and hosted platforms’ stdout collectors (PM2, Docker, Heroku, VPS journald). Nothing is sent to third-party log services by this app.

## Optional voice

Browser speech input and explicit read-aloud controls are behind `SpeechInput` and `SpeechOutput` interfaces in `lib/voice/`. Voice is never automatic or mandatory. The UI warns that browser services may use a vendor's servers. Unsupported or denied microphone access leaves typing available.

Dictation stays open until you stop it or about 5 seconds pass without new speech results; short pauses do not end it. Recognized text appears live and is updated in place, so repeated browser results cannot duplicate words, and any manual edit of the text ends dictation rather than overwriting what you typed. Actual microphone and speaker behavior still needs testing on your target device.

## Centralized architecture

- `app/globals.css`: Tailwind v4 theme tokens, shared component styles, responsive rules.
- `lib/styles.ts`: reusable UI variants and class-merging utility.
- `lib/data/exercises.ts`: exercises, duration choices, demo sample, skill descriptions, level labels.
- `lib/llm/`: provider abstraction, centralized prompts, validated schemas.
- `lib/observation/`: deterministic progression and exercise selection.
- `lib/auth/`, `lib/db/`: replaceable authentication and persistence boundaries.

## Tests

```bash
npm run typecheck
npm test                  # 7 unit / adapter / configuration tests
npm run test:db           # 9 real MongoDB replica-set integration tests
npm run build

# In another terminal, with the app running in demo mode:
npx playwright install --with-deps chromium
npm run test:e2e           # 5 browser / API integration tests
```

`TEST_BASE_URL` can point the browser tests at another running instance. Use a separate `MONGODB_DB_NAME` or dedicated cluster for browser/API test servers. Tests create temporary accounts and rate-limit records; one demo journey leaves its isolated demo note until expiration. Repeated rapid test runs can correctly trigger the authentication rate limit.

Automated checks cover the main journey, authentication, account deletion, user isolation, CSRF checks, input limits, duplicate completion, draft recovery, no remote page assets, selected accessibility rules, and malformed/error model responses. An additional `node tests/embedded-check.mjs` smoke test targets a server started with `COOKIE_EMBEDDED=true COOKIE_SECURE=true` and exercises login/logout through simulated HTTPS iframe origins. Automated accessibility tests are not a substitute for manual assistive-technology testing.

## Deployment notes and remaining work

The application uses a pooled MongoDB connection per Node process. Local storage is provided by the persistent replica-set volume; hosted storage is provided by Atlas, not the app server filesystem. Use the Node runtime (not Edge), configure Atlas network access and credentials, budget connection pools across application instances, and sanitize forwarded headers in a trusted HTTPS reverse proxy. Back up the database appropriately. The application and its database no longer have to run on the same server.

Before a public production launch: verify a real hosted/local model, add email verification and secure password recovery, establish backup/retention policies, audit authentication, test voice on real devices, and evaluate coaching quality. There is no email delivery or password reset flow in this MVP.
